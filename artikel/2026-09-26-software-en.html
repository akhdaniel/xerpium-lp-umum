Software House Project Management with Xerpium ERP: From Sprint Planning to Profitability

# Software House Project Management with Xerpium ERP: From Sprint Planning to Profitability

Running a software house is not only about writing clean code. It is about managing multiple delivery methodologies, keeping product backlogs under control, tracking sprint velocity, allocating the right engineers, and still knowing whether each project is profitable. When project data is scattered across separate tools, decision-making slows down and margins become difficult to defend.

Xerpium ERP addresses this problem by bringing software delivery operations into one connected system. It combines Scrum, Waterfall, Kanban, budgeting, team allocation, technology stack mapping, timesheet tracking, and reporting. For software houses, that means project managers, engineers, finance teams, and sales teams can work from the same operational truth.

Common Challenges in Software House Operations

Software houses typically face several recurring operational problems:

  • Inconsistent delivery methods across client projects, making standardization difficult.
  • Limited visibility into backlog readiness, sprint capacity, and velocity trends.
  • Weak control over project budgets, actual hours, and profitability.
  • Unclear team allocation and role-based capacity planning.
  • Disconnected technology portfolio data that is hard to present to clients.

Xerpium ERP is designed to address these challenges through project management modules that are connected to accounting, sales, HR, and technology tracking.

Xerpium ERP Modules for Software House Delivery

Scrum Framework

For agile teams, Xerpium supports a structured Scrum workflow. The product backlog holds user stories with story points, priority levels, acceptance criteria, and tags. Priority can be set as Low, Medium, High, or Critical. Story points estimate effort per user story, while sprint planning uses capacity planning based on available story points.

Each sprint has a specific sprint goal, timeline, and task list. User stories can be broken down into tasks in project.task, assigned to developers, and linked back to the backlog. Velocity tracking is auto-computed from completed points per sprint, and completion rate shows the percentage of backlog items finished in each sprint.

User Story & Backlog

Xerpium helps software houses maintain a clean product backlog. User stories follow the common format: As a... I want... So that... Each story includes acceptance criteria, story points, priority, tags, and an assigned developer. The status flow moves from Backlog to In Sprint, In Progress, and Done. When a story is assigned to a sprint, its state can change automatically.

Sprint Management

The sprint workflow follows Planning, Active, and Closed states. Xerpium validates that only one active sprint exists per project, helping teams avoid overlapping sprint confusion. A sprint includes capacity in story points, a goal, start and end dates, and all associated tasks. The sprint close wizard supports review and retrospective activities. Velocity history shows how performance changes from sprint to sprint.

Waterfall Methodology

For clients that require sequential delivery, Xerpium provides Waterfall project management. Projects are divided into phases with a defined sequence, start date, end date, and milestone. Each phase includes deliverables, phase tasks, and phase states: To Do, In Progress, Review, and Done.

Gate approval is required before moving to the next phase. Predecessor validation automatically ensures that a phase cannot start before its predecessor is complete. Gate history records who approved each gate and when, creating a clear audit trail.

Kanban & Hybrid

Not every project fits a pure framework. Xerpium supports a hybrid approach with a visual Kanban board in project.task. Tasks can be classified as Feature, Bug, Technical Debt, or Spike. Story points can be estimated directly at the task level, and tasks can be linked to a backlog user story or a Waterfall phase.

The methodology itself is flexible and can be selected per project. This allows a software house to run Scrum for product development, Waterfall for fixed-scope client work, and Kanban for maintenance or internal improvements, all inside the same ERP.

Budget & Profitability

Software house profitability becomes easier to monitor because Xerpium connects project budgets to actual delivered work. Each project supports a monetary budget and estimated hours. Contract types include Fixed Price, Time & Material, and Milestone Billing.

Actual hours are tracked automatically from timesheets. An average hourly rate is configurable per employee, with a default of Rp 150.000. Profitability is computed using the formula: (budget - actual cost) / budget × 100. Projects can be linked to a sale order, enabling billing and invoicing based on the agreed contract type. Multi-currency is supported through company currency settings.

Team Allocation

Xerpium integrates with the existing HR employee data using hr.employee. Project managers can allocate employees to projects with specific roles such as Project Manager, Business Analyst, Developer, QA Engineer, DevOps, and UI/UX Designer.

Each allocation includes a start date, end date, hours per week, and notes. Total hours are computed automatically from weeks multiplied by hours per week. The system validates that the end date is after the start date and that weekly hours are between 0.1 and 168, preventing unrealistic planning.

Technology Stack

Software houses often need to present their technical capabilities clearly. Xerpium includes a technology catalog with categories such as Frontend, Backend, Database, DevOps, Mobile, and Other. Technologies have a unique name constraint and color tags for visual coding.

Projects can be mapped to technologies using a many-to-many relationship. This enables stack filtering, stack diversity analysis across projects, and a portfolio view that can be used to show stack capabilities to clients.

Project & Accounting, Timesheet, Sales, HR, and Reporting

Xerpium connects project delivery to the wider business:

  • Budget tracking comes from the project budget field.
  • Timesheet entries through account.analytic.line are summed per project to calculate actual hours and hourly cost.
  • Projects can be created from a sale order, and contract type determines the billing method. Fixed Price supports single invoicing, while Milestone supports phased invoicing.
  • Team allocation comes from HR employees, with role assignment, hourly rates, and capacity planning per role.
  • Reporting includes sprint velocity reports, project profitability reports, phase completion reports, and team allocation utilization reports.

Business Benefits for Software Houses

  • One connected system for backlog, sprints, Waterfall phases, Kanban tasks, and budgets.
  • Better sprint predictability through capacity planning, velocity history, and completion rate tracking.
  • Clearer profitability control because actual timesheet hours feed cost tracking automatically.
  • More reliable team planning with role-based allocation and validation rules.
  • Stronger client communication through phase gate history and technology stack portfolio views.
  • Flexible delivery management by choosing Scrum, Waterfall, Kanban, or hybrid per project.

Example Use Case

A software house wins a fixed-price client project through a sale order. The project manager creates the project in Xerpium and selects Scrum as the delivery methodology. The team builds a product backlog with user stories, acceptance criteria, story points, and priorities.

During sprint planning, the manager sets a sprint goal and uses story point capacity to plan the sprint. Developers are allocated with roles such as Backend Developer and QA Engineer, with defined weekly hours. As the sprint progresses, team members log timesheet entries. Xerpium automatically calculates actual hours and actual cost. The budget field and average hourly rate allow the system to compute project profitability continuously.

At sprint close, the team reviews completed points and velocity. The technology stack is mapped to the project, so the client can see the approved stack in a portfolio view. Finance uses the sale order link and contract type for invoicing. Reporting gives management a clear picture of sprint velocity, phase completion, team utilization, and project profitability.

Conclusion

Software houses need more than a task board. They need an ERP that understands delivery frameworks and connects them to budget, people, and client billing. Xerpium ERP brings Scrum, Waterfall, Kanban, allocation, profitability, and technology stack management into one system, reducing operational friction and improving visibility.

If your software house is ready to standardize project delivery, control margins, and present technical capabilities more clearly, Xerpium ERP is built for that challenge.
