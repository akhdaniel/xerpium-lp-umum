# PLM in Xerpium ERP: Managing Engineering Change, BOM Revisions, and Approval Control

For manufacturers and product-driven businesses, the gap between engineering intent and production reality is often caused by one thing: uncontrolled change. When a bill of materials is updated outside a formal process, when a routing change is not communicated to the shop floor, or when an approval happens in an email thread instead of a controlled system, product quality and delivery timelines suffer.

Xerpium ERP addresses this with a dedicated Product Lifecycle Management (PLM) layer built around Engineering Change Orders (ECOs), revision-controlled bills of materials, dynamic approval stages, and structured document handling. It connects PLM directly to manufacturing, products, documents, and dashboards so that product changes remain visible, auditable, and linked to the operations they affect.

Common Challenges in Product Lifecycle Management

Many B2B manufacturers and distributors face similar PLM issues:

  • BOM revisions are managed through spreadsheets or duplicated product records, making it difficult to know which version is active.
  • Engineering change approvals rely on ad hoc emails or meetings, causing delays and unclear accountability.
  • Change impact is not systematically analyzed, so component quantity differences, routing updates, and by-product changes are missed until production.
  • Supporting documents such as SOPs, specification sheets, and drawings are disconnected from the BOM or operation they describe.
  • The audit trail is fragmented, making it hard to answer why, when, and by whom a product change was approved and applied.

How Xerpium ERP PLM Addresses These Challenges

Xerpium PLM is organized around ECOs, BOM revisions, approvals, dynamic stages, and document management. The following capabilities are directly available in the ERP suite.

Engineering Change Orders (ECO)

Every engineering change in Xerpium starts as an ECO. The system automatically generates a reference using the ECO/##### sequence, so each change request has a unique identifier without manual numbering.

Each ECO supports:

  • Description and priority tracking with Normal or High priority.
  • Change type configuration, such as applying the change on a Bill of Materials or Product Only.
  • Effectivity control, with options for As soon as possible or At Date using an effective date.
  • Colored tags for categorization.
  • Kanban states for visual tracking: Normal, Approved, or Blocked.

ECOs can also be categorized by ECO Type. Each type can have its own set of stages, and mail aliases can be configured so that inbound emails to a specific alias automatically create an ECO of that type. Smart counters track metrics such as the number of ECOs, approvals, approvals assigned to the current user, and validation counts. ECO types support multi-company configuration.

BOM Revision and Apply

Xerpium PLM includes controlled BOM revision. When a revision starts, the system copies the current BOM into a working copy, increments the version by one, and sets the new version as inactive while it is being edited. A previous BOM link is preserved for audit trail, creating a chain of BOM history.

When the ECO is applied, Xerpium activates the new BOM, deactivates the old one, and synchronizes operation documents to the new BOM operations. A version toggle flag allows an apply action without bumping the version again when appropriate. On apply, the product version is automatically incremented on the product template.

Change Impact Analysis

Before applying a change, Xerpium automatically calculates the impact of an ECO by comparing the current BOM with the proposed working copy. The analysis includes:

  • Component changes: add, remove, or update with quantity and unit-of-measure deltas.
  • By-product changes on the BOM.
  • Operation changes, including routing and work center changes with time cycle deltas.

The change impact is color-coded in the form view: green for additions, red for removals, and blue for updates. Rebase tracking fields capture conflicts when the upstream BOM changes while an ECO is in progress.

Approval Mechanism and Approval Types

Xerpium PLM builds approval control directly into ECO stages. Approval records are auto-generated, and mail activities are created for approvers automatically.

Approval types include:

  • Mandatory: must be approved before the stage can advance; the approval is considered complete only when status is approved.
  • Optional: can be approved but is not blocking; it is always considered approved for gating purposes.
  • Comment: captures comments without affecting approval status.
  • Constraint: a user cannot be assigned more than once per stage.

Stage gating prevents a stage from advancing if mandatory approvals are not complete. Only users defined in the approval template can approve or reject. Moving to another stage closes processed approvals and removes pending ones, while mail activities keep approvers informed.

Dynamic Stage Features

PLM stages in Xerpium are configurable and data-driven rather than hard-coded. Each stage supports:

  • Python hooks that execute when a record enters the stage.
  • Automated server actions on stage entry.
  • RBAC group restrictions that limit who can move a record to that stage.
  • Native state synchronization between stage and state field, including confirmed, progress, and done states.
  • Configurable back navigation for moving a record to a previous stage.
  • Approval templates linked to each stage.
  • A default stage that is automatically assigned when a new record is created.

Document Features

Xerpium PLM documents can be attached to any model using a polymorphic relation. The supported document types include:

  • File: PDFs, images, and other uploads via attachment, with automatic mime-type detection.
  • External link: Google Slides or other external URLs, opened through an action without file upload.
  • Text note: plain text content for quick notes or instructions, editable inline.

Documents can be rendered differently on kanban cards based on document type. Operation documents can be linked to a specific BOM operation, which is useful for SOPs. When an ECO is applied, operation documents are synchronized to the new BOM. Documents support a cover image for the ECO and file-type documents are duplicated with their attachments when copied. Multi-company isolation is applied through company_id.

Manufacturing Integration and Dashboards

Xerpium PLM is connected to manufacturing. Users can create an ECO directly from a Manufacturing Order with one click, and the BOM and product are automatically filled. The ECO links back to the manufacturing order, and manufacturing orders list their related ECOs.

BOMs and products also show ECO history and counts. When an ECO is applied, the new BOM version becomes active and operation documents are synced. Work center documents can be attached to routing work centers.

For visibility, Xerpium PLM includes a dashboard built on Dashboard Studio. The dashboard auto-refreshes every 300 seconds, applies filters automatically when opened, and combines ORM sources such as ECOs, BOMs, and products with SQL sources for aggregated data. It uses a green theme consistent with PLM branding and is visible to all PLM users.

Business Benefits of Xerpium PLM

  • A controlled, auditable ECO process from creation through approval and application.
  • Accurate BOM version history with previous BOM links and automatic product version increments.
  • Early visibility into component, by-product, and routing changes before production is affected.
  • Clear approval accountability with mandatory, optional, and comment approval types.
  • Strong integration between PLM, manufacturing orders, products, and documents.
  • Reduced risk of using outdated BOMs or missing SOP changes on the shop floor.
  • A single audit trail through mail thread chatter and structured ECO records.

Example Workflow: From Manufacturing Issue to Controlled Product Change

A production planner identifies an incorrect component quantity in a manufacturing order. From the manufacturing order, they create an ECO with one click. The ECO is automatically linked to the BOM and product, and a new BOM revision is started as a working copy.

The planner updates the component quantity. The change impact analysis shows the component delta with color-coded information. The ECO moves through a configured approval stage where mandatory approvers receive mail activities and approve the change. Once approvals are complete, the ECO is applied: the new BOM becomes active, the old BOM is deactivated, the product version increments, and operation documents are synced. The entire history remains in the ECO chatter for audit.

Conclusion

Xerpium ERP brings product lifecycle management into the same system as manufacturing, inventory, and product data. Instead of managing BOM changes in separate spreadsheets or disconnected email threads, companies can use structured ECOs, controlled BOM revisions, impact analysis, approval gating, and synchronized documents. The result is a cleaner path from engineering intent to controlled production change.
